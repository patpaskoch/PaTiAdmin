# Testing

## Automated: `tools/check.sh`

| Step | What it checks | Tool |
|---|---|---|
| syntax | every `.lua` compiles (Lua 5.1 grammar) | `tools/lua/run.lua syntax` |
| luacheck | undefined/unused variables, forbidden globals (per-addon allow list) | `luacheck` + `.luacheckrc` |
| tests | `tests/*_spec.lua` of the repo | `tools/lua/test.lua` (busted-compatible subset) |
| locales | enUS present, no unknown/duplicate keys, files load, values are strings; untranslated = warning | `tools/lua/locales.lua` |
| toc | Interface/Title/Version (SemVer), SavedVariables names, every referenced file exists (incl. XML includes), no stray characters, no `Dependencies`/`OptionalDeps` on PaTi addons, every `.lua` outside `tests/` is loaded (error); missing Notes/Author (warning) | `tools/lua/toc.lua` |
| shared | `Shared/` matches its `.manifest` (no hand edits) | bash |
| ci-file / release | `.github/workflows/ci.yml` and (addons) `release.yml` equal the templates | bash |
| ingame | `INGAME_TESTING.md` present (addons), IDs unique and well-formed, `[x]` only with a latest `✅ VERIFIED` | `tools/ingame-status.sh --check` |
| package | a real zip is built in a temp folder: one folder `<Addon>/`, TOC inside, content = package list, no development files | `tools/package.sh --verify` |

```
PaTiAdmin/tools/check.sh                       # everything next to PaTiAdmin
PaTiAdmin/tools/check.sh ../PaTiAddons/PaTiHeal
LUA=/path/to/luajit LUACHECK=/path/to/luacheck PaTiAdmin/tools/check.sh
```
Results: PASS / FAIL / SKIP (tool missing locally) / NONE (nothing to check yet). Exit code ≠ 0 on any FAIL.

## Unit tests

- Location: `<repo>/tests/<topic>_spec.lua`. Runner: `describe`, `it`, `before_each`,
  `assert.equal/same/is_true/is_false/is_nil/truthy/falsy/matches/has_error` — the busted API, so the
  specs can move to busted unchanged if it ever becomes installable everywhere.
- Load addon files like WoW does: `require("wow_api").loadAddonFile(path, ns)` passes `(addonName, ns)`.
- Mocks: `PaTiAdmin/tests/mocks/wow_api.lua`. Add a mock only for a function the code under test calls.
  Do not mock frames, secure templates or combat — those are manual tests.
- What to test: defaults/config, SavedVariables migrations (old table in → new table out, no data lost),
  version parsing, locale lookup/fallback, protocol encode/decode/validation, quest comparison,
  state transformations, pure helpers.
- Current coverage: PaTiAdmin tools (TOC parser incl. the `` `r`n `` regression, release rules, changelog sections,
  locale validator), PaTiShared locale handling, PaTiHeal (bindings → attributes, migration incl. HoT settings, ranks,
  health percent, secret-value helpers, profiles, HoT matching/texts), PaTiAuras (states, config, spellbook, profiles,
  unreadable auras → UNKNOWN, secret names/flags, Priest healing auras), PaTiGroup (settings, marker slots, secret-value
  helpers, 1/true flags), PaTiTank (migration, collapse, threat value, aggro states, threat adapter with mocks),
  PaTiQuest (migration, collapse, quest lines), PaTiDungeon (migration, collapse, status incl. 1/nil flags).

## Regression rule

Bug → reproduce → failing test if the logic is testable → fix → test green → full `check.sh`.
If not testable outside WoW, add (or reopen) the matching test in the addon's `INGAME_TESTING.md`: `❌ FAIL <date>`
with what the owner saw, later `🔧 FIX IMPLEMENTED <date>` + `MANUAL RETEST REQUIRED`.

## Manual WoW tests (CI cannot do these)

The owner runs them in the real client. Needed for: secure click casting, combat lockdown, protected actions, taint,
raid markers, visuals/layout (UI scale 0.64–1.0, locked/unlocked, long German/zh/ko strings), fonts (zhCN, zhTW, koKR
on the deDE client), real group/dungeon situations, addon communication. Helpful: `/console taintLog 1` and afterwards
`Logs/taint.log` checked for PaTi entries; `/<cmd> debug` output copied into the report (PaTiAuras weapon
imbues: `/pa auras` once without and once with the imbue).

Every concrete test lives in exactly one place: the addon's `INGAME_TESTING.md` (below). This file only has the rules.

## In-game test files

Every runtime addon (PaTiHeal, PaTiAuras, PaTiTank, PaTiGroup, PaTiQuest, PaTiDungeon, PaTiAlerts, PaTiSocial, PaTiSuite) has
`INGAME_TESTING.md` in its repo root: the permanent, Git-tracked record of what was tested in the real WoW client, what
is still open and what failed. PaTiShared has none (not a runtime addon). Not shipped in the release zip (`*.md`).
Overview of all eight: [`INGAME_TEST_STATUS.md`](INGAME_TEST_STATUS.md), generated by `tools/ingame-status.sh`.

**Rule: a test may be marked `[x]` only when the owner performed it in the real World of Warcraft client and
explicitly confirmed it as successful.** Unit tests, smoke tests, CI, code review, mocks, static analysis, packaging,
an agent's assumption or "looks right in the code" never count. Without the owner's confirmation the box stays `[ ]`.

Format (one test = one line with a permanent ID `PT-<ADDON>-NNN`, results as indented lines below it, newest last):

```
- [ ] PT-AURAS-001 Addon lädt ohne Lua-Fehler                      open: never confirmed in the client

- [x] PT-AURAS-001 Addon lädt ohne Lua-Fehler                      verified
  - ✅ VERIFIED 2026-09-30
  - Laden und `/reload` ohne Lua-Fehler.                          optional short observation

- [ ] PT-AURAS-053 Rockbiter aktivieren → ACTIVE                   failed: the box stays OPEN
  - ❌ FAIL 2026-09-30
  - Waffe erkannt, Imbue bleibt UNKNOWN.
  - 🔧 FIX IMPLEMENTED 2026-09-30                                  a fix never ticks the box
  - MANUAL RETEST REQUIRED

- [x] PT-AURAS-053 Rockbiter aktivieren → ACTIVE                   after the owner's retest; history stays
  - ❌ FAIL 2026-09-30
  - 🔧 FIX IMPLEMENTED 2026-09-30
  - ✅ VERIFIED 2026-10-01
  - Rockbiter an/aus/an korrekt erkannt.

- ~~PT-AURAS-017 alter Test~~                                      no longer relevant; the ID is never reused
  - RETIRED 2026-10-10 – Feature entfernt.
```

- IDs are never renumbered or reused. New tests get the next free number of their section.
- Sections per file: Installation / Laden, Fenster, SavedVariables, Sprachen, the addon's features, Combat / Sicherheit,
  Combined. Only features that exist in the code on `main` — nothing planned.
- Integration tests (PaTiAlerts) live in the producer's file (PaTiTank, PaTiAuras, PaTiHeal); PaTiAlerts links to them.
- A feature or fix that needs new manual tests adds them in the same task (open). A test whose behaviour a fix
  changed gets `🔧 FIX IMPLEMENTED <date>` + `MANUAL RETEST REQUIRED`.
- Owner results: "Rockbiter works now" → PT-AURAS-053 `[x]` + `✅ VERIFIED <date>`; "does not work" → box open +
  `❌ FAIL <date>` + what was seen. If it is unclear which test is meant, ask — never tick blindly.
- `tools/check.sh` (step `ingame`) fails if the file is missing, an ID is duplicated or malformed, a `[x]` has no
  `✅ VERIFIED` as its latest result, or an open box has one.

Questions answered straight from Git:

```
PaTiAdmin/tools/ingame-status.sh                     # verified / failed / open per addon
PaTiAdmin/tools/ingame-status.sh --list failed       # every failed test (incl. fixed, retest pending)
PaTiAdmin/tools/ingame-status.sh --list retest       # "what do I test in WoW tonight?" – fixes to confirm first
PaTiAdmin/tools/ingame-status.sh --list open         # everything never tested yet
grep -n '\[x\]' PaTiAddons/PaTiTank/INGAME_TESTING.md   # what is confirmed for PaTiTank
```

## Fresh install test

"Does the downloaded zip work like for a stranger?" Per addon, once per release candidate:

1. Build the zip: `PaTiAdmin/tools/package.sh ../PaTiAddons/<Addon>` (or take it from the draft release).
2. Unpack it: exactly one folder `<Addon>/` must appear, with `<Addon>.toc` directly inside.
3. Move every PaTi folder out of `Interface/AddOns/` (keep `WTF/` — or also test once with its SavedVariables removed).
4. Copy only `<Addon>/` into `Interface/AddOns/`, start WoW, enable only this addon.
5. Login: the addon is listed with its description and loads; no Lua error.
6. `/reload`; open the main window and the settings (`/<cmd> settings`); `/<cmd> test`; no Lua error.

**Independence test:** the fresh install test once for each addon alone (PaTiHeal, PaTiAuras, PaTiTank, PaTiGroup,
PaTiQuest, PaTiDungeon, PaTiAlerts, PaTiSocial). **Combined test:** all together: every window opens, every slash command answers the right
addon (`/ph /pa /pt /pg /ptg /phq /pd /pal /psocial /psuite`), each settings window saves its own values, no Lua or taint error.


## Release testing (per release candidate)

Order: 1 loads · 2 UI · 3 main feature · 4 combat · 5 `/reload` · 6 SavedVariables · 7 all addons together ·
8 Lua/taint.

1. Fresh install test and independence/combined test (above) — tests `…-001` to `…-005` and the Combined section.
2. `tools/ingame-status.sh --list retest`: every fix waiting for a retest in the changed addons.
3. The main-path tests of the changed features in the addon's `INGAME_TESTING.md` (its feature sections, Combat).
4. Enter each result in the file (owner-confirmed only); commit it with the message "In-game results <Addon> <date>".

Beta/release gate (main paths VERIFIED, FAILs assessed): [`RELEASE.md`](RELEASE.md#in-game-verification).
